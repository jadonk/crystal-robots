Robot manual

A field guide to writing programs that fight on a virtual battlefield.

What crystal-robots is

crystal-robots is a Crystal-flavored take on Tom Poindexter’s CROBOTS (1985). Its WebAssembly compiler grows out of Colin Eberhardt’s chasm. Here, the compiler and the battle run entirely in your browser.

You write a small robot program, test it against others, and watch the match. The language is a focused subset, so use the forms described below rather than assuming all of Crystal is available.

Your first robot

Paste this complete program into the robot editor and choose Fight:

main("Scout") do
  drive(0, 50)
  while true
    range = scan(0, 10)
    if range > 0
      cannon(0, range)
    end
    sleep
  end
end

main("Scout") do names your robot and opens its program. drive(0, 50) asks it to head east at speed 50. while true repeats the body. scan(0, 10) looks east within ten degrees; it returns the closest robot’s distance, or zero. When the distance is positive, cannon(0, range) fires toward it. sleep spends a turn while motion continues. Each end closes its matching block. Try another angle or speed and watch the replay.

The language

Programs use integer expressions and line endings or semicolons between statements. Comments start with # and run to the end of a line. The only string literal used by this subset is the robot name in main("Name") do … end. A top-level def declares a function; return may give back a value. global(name, init) declares mutable shared state; a top-level assignment also makes an implicit global constant. Function definitions are collected before checking calls, so source order does not matter.

# Keep a shared shot count.
global(shots, 0)
LIMIT = 3

def double(value)
  return value * 2
end

main("Counter") do
  shots += 1
  puts double(shots) + LIMIT
end

Numbers are whole, signed integers. Use + - * / // % for arithmetic, unary -, and == != < <= > >= for comparisons. Both / and // use CROBOTS-style floored integer division; dividing by zero yields zero, including for %. Logical and/or are written &&/|| or &/|; ^ is bitwise integer xor. Both sides of an and/or expression are evaluated; conditions treat zero as false and nonzero as true. true and false are accepted literals. Assign with =, +=, -=, *=, or %=.

Control flow includes if/elsif/else, while, until, break, and case/when/else. Parentheses group expressions. This example exercises those forms:

main("Decisions") do
  count = 0
  while count < 4
    count += 1
    if count == 1
      puts count
    elsif count == 2
      puts count * 2
    else
      puts count % 2
    end
    if count > 3
      break
    end
  end
  until count == 0
    count -= 1
  end
  case count
  when 0
    puts true
  else
    puts false
  end
end

The parser does not implement all Crystal syntax: no floats, arrays, for, next, or unary !. The parser has work budgets of 20,000 reduction passes and 2,000,000 emitted glyphs. For portability, keep a robot below 20 KB of source. The browser editor does not currently enforce that source-size guideline.

The battlefield

The field is 1,000 × 1,000 meters . Coordinates begin at the lower left. Positions use 10 clicks per meter . Motion updates every 15 charged cycles . Speed is clamped to 0–100 and changes by at most 10 per motion update . At speed 100, a robot covers 70 clicks, or 7 meters, per update . A heading change only takes effect when current speed is 50 or less ; if it is faster, the robot brakes first.

scan(degree, resolution) checks within ± the requested resolution, clamped to 0–10 degrees , and reports the closest robot’s distance in meters or zero. cannon can target at most 700 meters . Each robot has two missile slots and waits 15 motion updates between shots . Missiles fly 500 clicks, or 50 meters, per update . An explosion deals 10% damage inside 5 meters, 5% inside 20, or 3% inside 40 . Hitting a wall or another robot deals 2% damage ; robots are eliminated at 100% .

The reference interpreter charges 1 cycle for a fetch or constant, 1 for an operator, 1 for a store, 2 for a builtin, 3 for a user call, 1 for a branch, and 1 for a statement . Robots take turns at this cycle granularity. The default match limit is 500,000 cycles ; a match can end earlier when only one robot remains.

How it works

The parser first tokenizes text into glyphs, then makes repeated whole-string reduction passes until one program glyph remains. The derivation notes explain the order and precedence. The checker catches unknown names, wrong call arity, and misplaced control flow. The reference interpreter executes the parsed tree; the WASM emitter turns it into a WebAssembly module.

The site’s crystal-robots.wasm is itself the compiler and battle entry point, built from Crystal for wasm32-unknown-wasi. In the browser, the stepwise robot runner and battle engine advance one charged cycle at a time and record the match for replay.

Challenge

The guided challenge walks you from your first move to a tournament entrant. Each goal runs a real browser battle and shows the deciding replay. Your source and progress are saved in this browser when storage is available.

Tournament

Pick 3 to 8 entrants in the tournament, choose a seed, and share the link. Pool standings lead to a bracket; select any fight to replay its recorded entrants and seed. Your saved robot appears as an entrant.

Running it yourself

Clone the repository, then run these commands from its root:

git clone https://github.com/jadonk/crystal-robots.git
cd crystal-robots
crystal spec
crystal run ci.cr
crystal run ci.cr -- --with-wasm32
crystal run ci.cr -- --with-wasmer

--with-wasm32 builds the browser compiler and generated JSON. --with-wasmer runs optional WebAssembly runtime specs. The CI command also builds bin/crystal-robots. Use bin/crystal-robots -h for help; key flags are -t ROBOT (parser derivation), -i (interpret), -c ROBOT and -o OUTFILE (compile to WASM), --ticks (cycle imports when compiling), -m MATCHES, -l CYCLES, and --seed=SEED for matches. -v prints the version.
